# 發電機組 3D 檢視器 + 安裝排程

左為 RZ2000 發電機房的 three.js 檢視器，右為 24 步驟安裝排程甘特圖，
中間分隔線可拖曳。渲染設定沿用 `../../TaipeiCityHall/scada-vue` 的 `ThreeFloorViewer.vue`。

## 執行

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 產出 dist/（含 23 MB 模型）
npm test         # vitest
```

## 模型來源

`public/models` 是指向專案根目錄 `3D/` 的 symlink，模型更新會自動反映，
build 時 Vite 會把實體檔案複製進 `dist/models/`。

21 個 GLB 共用同一組場域座標（公尺、Y-up），以原點載入即自動組裝。
未使用 Draco 壓縮，因此不需要 `DRACOLoader`。

| `src/stores/viewer.ts` | UI 狀態（顯示集合 / 隔離對象 / 爆炸係數 / 載入狀態） |

## 操作

- **勾選框**：顯示／隱藏單一構件；群組標題的勾選框可整組切換。
- **點構件名稱**：隔離該構件，其餘變半透明；再點一次取消。
- **爆炸圖滑桿**：0–100%，設備沿徑向散開；機房外殼在 60% 時完全透明。
  地坪與外殼不參與位移。
- **隱藏外牆**（右上角）：外牆整個拿掉。與側欄的「機房外殼」勾選框是同一個狀態，
  兩邊操作互相反映；外牆隱藏時「外牆透視」自動禁用。
- **外牆透視**（右上角）：外牆變 16% 半透明但保留輪廓，看得到牆的位置又能看穿。
  與爆炸淡出取較透明者。
- **重設視角**：相機回到預設的四分之三視角。

## POI 標記

標在 3D 構件表面上的標記，可嵌入 YouTube／Vimeo 影片或其他網址。

| 檔案 | 職責 |
|---|---|
| `src/data/pois.ts` | 預設 POI 清單（目前為空，含格式範例） |
| `src/lib/embedUrl.ts` | 網址 → 嵌入網址的轉換與播放區間（純函式，33 個測試） |
| `src/lib/timecode.ts` | 時間碼解析與格式化（純函式，32 個測試） |
| `src/stores/poi.ts` | 使用者新增／修改／刪除，疊在預設之上，存 localStorage |
| `src/three/PoiLayer.ts` | CSS2D 標記，掛在所屬構件底下 |
| `src/components/PoiCard.vue` | 3D 上浮出的卡片 |

操作：工具列「標記」開啟編輯模式後，點模型表面即新增。拖曳仍可轉動視角
（按下與放開的位移超過 4 px 就不視為點擊）。點標記展開卡片，卡片釘在 3D 點上，
會跟著旋轉與縮放移動。

**標記掛在構件的子節點下**，所以構件被爆炸圖推開、隱藏或因高程修正位移時會跟著走，
不需要另外同步座標。`CSS2DRenderer` 不看祖先的 `visible`，這點由 `PoiLayer.update()`
每幀補上。

### 播放區間

編輯 POI 時可設定「開始／結束」，只對 YouTube 與 Vimeo 顯示。輸入格式接受
`90`、`1:30`、`1:02:03`、`1h2m3s`，離開欄位即解析（`src/lib/timecode.ts`）。

- YouTube 轉成 embed 的 `start` / `end` 參數。
- **Vimeo 只支援起點**（`#t=90s`），播放器沒有結束參數，因此結束欄位會停用。
- 結束早於或等於開始時擋下並提示；即使繞過介面寫進資料，`toEmbed` 也會忽略該終點，
  不會產生播不了的網址。
- 起點 0 不寫進網址，省得多一個沒有作用的參數。
- YouTube 的 `end` 以關鍵影格對齊，實際停止點可能差一兩秒。

未設定起點時，沿用網址自帶的 `t=` 參數；明確設定則覆蓋它。

### 網址處理

YouTube 的 watch／youtu.be／shorts／embed／live 各種形式都會轉成 `youtube.com/embed/`，
並保留播放清單參數；Vimeo 轉成 `player.vimeo.com`。
其他網址仍會嘗試嵌入，但標示為不可靠並一律附上「在新分頁開啟」——**多數網站會用
X-Frame-Options 或 CSP 拒絕被嵌入，而且瀏覽器不會回報錯誤，只會顯示一片空白。**

⚠️ iframe **不要**設 `referrerpolicy="no-referrer"`。YouTube 需要 referer 驗證嵌入來源，
少了它播放器會回報 Error 153（實測踩過）。

### 已知限制

高程修正（見下節）位移的是構件底下的個別機組節點，POI 則掛在構件根節點上。
因此若日後調整 `UNIT_Y_OFFSET` 的值，掛在右側機組上的 POI 不會跟著移動，需重新放置。

## 機組高程對齊

機房內有兩台機組，多數 GLB 以兩個頂層節點各放一份。**19 個設備檔中有 7 個的兩份高度
不一致**，最嚴重的是發電機本體差 1.01 m（一台坐在避震基座上、另一台陷進去）。

這是模型本身的問題。`src/data/alignment.ts` 以節點層級的 Y 位移在載入時修正，
與參考專案 TaipeiCityHall 的 `FLOOR_Y_OFFSET` 同一個做法。模型日後在 Blender 修好，
把對應項目從表裡刪掉即可。

| 構件 | 右側需位移 |
|---|---|
| p09 發電機組本體 RZ2000 | −1.0146 |
| p19 匯流排 | +0.6769 |
| p06 組合式煙囪 16" | +0.4978 |
| p22 缸套加熱電盤 | −0.4759 |
| p04 消音器重型吊架 | −0.3020 |
| p13 消音箱風罩 | −0.1758 |
| p08 發電機組用避震基座 | −0.0703 |

**這是「一律對齊左側那一份」的結果，不是逐件依實體參照校正的結果。** 已知副作用：

- **p06 組合式煙囪**：右側原本中心 16.48 對準穿牆蓋板（蓋板中心 16.50），對齊後兩根
  煙囪都變成 16.98，比蓋板高 0.48 m。
- **p04 消音器重型吊架**：右側原本底部 17.11 坐在消音器頂面（17.01）上方，對齊後
  兩組吊架都變成底部 16.80，穿進消音器 0.21 m。
- **p09 發電機本體**：左側那一份原本就比避震基座頂面低 0.68 m，對齊後兩台都是如此。

若要改成依實體參照逐件校正，把上表的值換掉即可，程式不用動。

## PBR 材質

模型匯出時 **26 種材質裡有 21 種是 `roughness = 1.0`**。金屬（`metalness = 1`）
在粗糙度 1.0 下完全散射、沒有連貫反射，在 IBL 下就渲染成一片死灰——這是所有金屬
原本看起來像灰色黏土的原因。除了水泥基座之外，模型也完全沒有貼圖。

材質名稱在各 GLB 之間共用且語意化（`metal` 出現在 11 個檔、`steel` 6 個），
因此 `src/three/materials.ts` 以**材質名**為索引建設定檔，比逐構件設定精準。

| 檔案 | 職責 |
|---|---|
| `src/three/materials.ts` | 材質名 → PBR 參數；逐構件覆寫；MeshStandard → MeshPhysical 轉換 |
| `src/three/detailMaps.ts` | 程序式粗糙度／法線貼圖（canvas 產生，無外部檔案） |
| `src/three/plantEnvironment.ts` | 供 PMREM 的程序式機房環境 |

三件事一起做才有效果：

1. **材質參數**：`metal` 鍍鋅鋼 rough 0.42、`steel` 不鏽鋼 0.32、`鈦` 鍍鋅角鋼 0.55、
   `gray_metal` 拉絲不鏽鋼 0.33 + anisotropy 0.65。烤漆類（`body`／`generate`）
   金屬度降到接近 0 再加 clearcoat，而非模型原本的 metalness 0.77。
2. **程序式細節貼圖**：完全均勻的金屬一看就是 CG。用 canvas 產生極細微的粗糙度與
   法線變化，`brushed` 版本沿 U 方向拉長做拉絲效果。只在模型沒有自己的貼圖時才補，
   不會蓋掉水泥基座的真實貼圖。
3. **環境反射**：金屬的立體感幾乎全來自環境。three 內建的 `RoomEnvironment` 是均勻
   柔和的攝影棚，金屬只會得到一片平均的灰。改用程序式機房場景——深色地坪、天花板
   數條長形燈槽、單側較亮的開口——長燈槽會在圓管與平板上映出細長高光。

逐構件覆寫目前只有一項：消音器的材質命名為「銅」，但實務上消音器是鍍鋅／不鏽鋼件，
只有匯流排與缸套加熱電盤的「銅」是真的導體銅。

`yellow_glass` 帶 `KHR_materials_transmission`，改參數會破壞透光，直接跳過。

## 排程面板（四個分頁）

右側面板頂部分頁：**甘特圖 / WBS / 網圖 / S 曲線**，四者共用同一份排程資料與選取狀態，
點任務都會在 3D 中隔離對應構件。頂部固定顯示 PERT 摘要（期望工期、σ、準時機率）。

### PERT 三點估算

排程採用**期望工期 te = (O + 4M + P) / 6**，而非單點工期。O/P 未在資料檔指定時，
由 `defaultThreePoint` 依 M 推算（O = 0.8M、P = 1.6M，並確保 O ≤ M < P）——
**這只是讓功能一開始就能用的起始值，實際數字應由現場經驗填入**，在 WBS 分頁直接改。
改任一欄會自動維持 O ≤ M ≤ P。

專案變異數只沿要徑累加（PERT 的標準假設）。這會低估風險，因為非要徑分支也可能
因延遲而變成要徑。

⚠️ 採用小數 te 之後，浮時會出現 4.44e-16 等級的浮點誤差。要徑判定必須用容差
（`FLOAT_EPSILON`）而非嚴格等於零，否則整條要徑會斷開——實測踩過，
斷掉的要徑還會讓變異數少算、把準時機率算得過於樂觀。

### WBS

第一層為階段（`PHASES`），第二層為個別步驟，代號如 `2.1`。階段列彙整該階段的
工作量、起訖、跨距與加權完成度；可摺疊。O/M/P 三欄可直接編輯。

### 網圖（PDM 前導圖）

活動置於節點（AON），方格分三列顯示 `ES / te / EF`、`WBS + 名稱`、`LS / 浮時 / LF`，
要徑以紅色串連，養護 lag 標在箭線上。

版面由 `src/lib/network.ts` 計算：依最長前置路徑分層（保證箭線一律由左往右），
層內以重心法迭代三輪降低交叉。純函式，有交叉數與穩定性測試。

### S 曲線與實獲值

- **計畫值 PV**：各活動工作量在其計畫區間內線性累積。最早開始與最晚開始各一條，
  中間填色即「香蕉包絡」。
- **實際 EV**：**資料裡沒有實際進度的時間序列**，每個步驟只有當下的完成度。
  因此實際曲線靠 `progressLog` 逐次累積——每次調整完成度時自動記錄一筆
  （同一天只留最後一次），也可手動按「記錄目前進度」。開工日必然是 0%，
  第一筆歷程不在第 0 天時會補上原點。
- **資料日期**：進度模擬開著時用游標，否則用今天。
- 指標：SPI = EV / PV、落後／超前天數（目前實獲值在計畫曲線上對應的日子減資料日期）。

系列色 `#3b82f6`（計畫）與 `#d97706`（實際）通過 dataviz 六項檢查
（深色底 #162033，CVD 最差配對 ΔE 30.2，對比皆 ≥ 3:1），並以直接標示與圖例
確保識別不只依賴顏色。

| 檔案 | 職責 |
|---|---|
| `src/lib/pert.ts` | 三點估算、常態近似、完工機率（27 個測試） |
| `src/lib/network.ts` | 網圖分層與減少交叉（14 個測試） |
| `src/lib/scurve.ts` | S 曲線與實獲值（26 個測試） |
| `src/components/gantt/SchedulePanel.vue` | 分頁容器與 PERT 摘要 |
| `src/components/gantt/WbsView.vue` · `NetworkView.vue` · `SCurveView.vue` | 三個新視圖 |

## 安裝排程甘特圖

24 個步驟來自 `../process/發電機安裝24步驟 (1).xlsx`。**該檔只有項次與名稱，
沒有工期、日期或相依關係**，因此 `src/data/installSteps.ts` 的排程是依機電施工邏輯
建立的草案。與 xlsx 項次順序的唯一差異：「3 設備安裝放樣」提前為第一步，
因為要先放樣才知道基座澆在哪。

| 路徑 | 職責 |
|---|---|
| `src/data/installSteps.ts` | 24 步驟：項次／名稱／對應構件／工期／前置／養護 lag |
| `src/lib/schedule.ts` | 要徑法排程引擎（純函式，23 個單元測試） |
| `src/stores/schedule.ts` | 排程狀態 + localStorage |
| `src/components/gantt/` | 甘特圖介面 |

操作：

- **拖長條**改開工日、**拖右邊緣**改工期，下游任務自動重排；也可直接改列上的數字欄位。
- **點任務**在 3D 中隔離對應構件。5 個步驟沒有 3D 模型（2 變壓器水泥基座、
  3 放樣、18 升壓變壓器、23 本體配線、24 煙囪保溫），名稱顯示為灰色，點了不動 3D。
- **進度模擬**：時間軸上的游標可拖曳，3D 只顯示游標日期前已完工的設備。
  開啟時會自動打開「外牆透視」，否則設備在機房裡看不見。
- **播放安裝過程**：游標自動從第 1 天走到最後一天，右側可選 0.5×–8× 倍速
  （1× 為每天 420 毫秒）。播放中改倍速立即生效，不必等當前這一天走完。倍速會記住。

排程以連續日（含週末）計算，週末在時間軸上以底色標示但不跳過。混凝土養護等待
本來就是連續日，若改成工作日制會與工期的語意不一致。

## 視窗尺寸

框景距離依 `camera.aspect` 計算，視窗變窄模型會被裁掉。因此在使用者第一次用滑鼠
操作相機之前，resize 會自動重新框景；一旦在 3D 畫面上按過滑鼠就視為使用者接手，
之後改由「重設視角」處理。
